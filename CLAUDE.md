# Теория углов в теннисе — правила проекта

Общение с владельцем и интерфейс приложения — **на русском**. Всё ниже уже согласовано с владельцем; пересказывать и переспрашивать не нужно.

## Что это

Мини-приложение по «учению об углах» в теннисе: корт сверху. Пользователь ставит соперника (красная ракетка), приложение:

- строит два крайних луча (предельные углы удара соперника);
- ставит игрока (зелёная ракетка) на биссектрису угла между лучами, на пересечении с его задней линией;
- затеняет зону приёма.

Режимы: «Розыгрыш» и «Подача». Платформы: веб (GitHub Pages), iPhone (PWA: Safari → «На экран Домой»), Telegram Mini App. Нативное iOS-приложение (Capacitor) не планируется — отдельное решение владельца.

## Файлы

- `index.html` — всё приложение (HTML + SVG + JS).
- `manifest.json`, `sw.js` (офлайн-кэш), `README.md`.
- Иконки: `icons/icon-192.png`, `icons/icon-512.png` (временные, сгенерированы). На них ссылаются `manifest.json`, `sw.js` и `<link rel="apple-touch-icon">`.

Публикация: GitHub Pages, ветка `main`, корень. После пуша в `main` сайт обновляется сам за 1–2 минуты; ссылка не меняется.

## Правила работы

- Один файл `index.html`, SVG + чистый JS, **без зависимостей и сборки**. Единственное исключение — `telegram-web-app.js` (вызывает `Telegram.WebApp.ready()` и `expand()` при наличии).
- Управление через pointer events, у SVG `touch-action: none`. Нажатие или перетаскивание в любом месте корта двигает красную ракетку (с ограничениями режима).
- Картинка целиком помещается на экран iPhone по ширине и высоте: SVG `max-width: 300px`, `viewBox="0 0 284.55 496.55"`.
- **При каждом изменении поднимай версию кэша в `sw.js`** (`tennis-angles-vN` → `vN+1`), иначе на телефоне останется старая версия.
- Масштаб и размеры корта — по ITF, не искажать.
- Коммиты короткие, на русском. Коммит/пуш делает кто-то один: владелец пользуется GitHub Desktop, поэтому по умолчанию Claude только правит файлы, а коммитит/пушит, лишь когда об этом попросили.
- Владелец даёт правки короткими визуальными фразами. Если формулировка допускает два прочтения — выбери разумное и прямо назови допущение в ответе.
- Новые неподтверждённые допущения дописывай в раздел «Допущения» этого файла.

## Геометрия

Масштаб 15 px/м. ITF: длина 23.77 м, ширина пар 10.97 м, одиночного 8.23 м, линия подачи в 6.40 м от сетки.

Координаты (корт по центру, отступы 60 по бокам и 70 сверху/снизу), `W = 284.55`, `H = 496.55`:

| Элемент | Значение |
|---|---|
| Внешний прямоугольник (пары) | x=60, y=70, 164.55 × 356.55 |
| Боковые одиночного | x = 80.55 и x = 204 |
| Центральная линия | x = 142.275 |
| Задние линии | y = 70 (верх, сторона красной), y = 426.55 (низ, сторона зелёной) |
| Сетка | y = 248.275; полоса x 55…229, y 244.275…252.275 |
| Линии подачи | y = 152.275 и y = 344.275 |
| Центральная линия подачи | x = 142.275 между линиями подачи; метки центра на задних линиях |

- Красная (соперник) — верхняя половина. Зелёная (игрок) — нижняя, по Y всегда на задней линии (y = 426.55), по X ограничена только краем экрана (5…W−5).

### Режим «Розыгрыш»

- Красная: x ∈ [5, W−5] (в т. ч. за боковыми), y ∈ [5, netY−5].
- Крайние лучи идут из красной через точки на боковых одиночного в 22.5 px (1.5 м) за сеткой: `touchY = netY + 22.5`.
- Выход за боковые: если `px < 80.55`, левый луч идёт через (80.55; 426.55) — пересечение левой боковой с нижней задней. Аналогично справа: `px > 204` → (204; 426.55). Между боковыми — точка у сетки.
- Зона приёма: P → (лев. боковая, leftPtY) → (лев. боковая, 426.55) → (пр. боковая, 426.55) → (пр. боковая, rightPtY) → P.
- Игрок: биссектриса = нормированная сумма единичных векторов лучей; точка её пересечения с y = 426.55, X ограничен краями экрана.

### Режим «Подача»

- Красная двигается только вдоль своей задней линии между боковыми одиночного; Y = `topBaselineY − 10 = 60`.
- `px < 142.275` → лучи в правый квадрат подачи напротив (диагональ), иначе — в левый. Квадрат: от центральной линии подачи до боковой одиночного, от сетки до y = 344.275.
- Точка пересечения луча с боковой линией квадрата — в 45 px за сеткой (вдвое больше, чем в розыгрыше).
- Игрок — тем же способом (биссектриса → y = 426.55).

### Лучи и мячи

- Лучи продолжаются за точку пересечения до границы видимой области (функция `exitPoint`), не обрезаются по задней линии и не вылезают за экран.
- Вдоль лучей — статичные мячи: r = 3, первый в 28 от ракетки, шаг 48, не более 7 на луч, за концом луча скрываются.
- Пунктирная белая линия — биссектриса от красной к зелёной.

## Визуальные решения

- Цвета: фон вокруг корта `#0b3d68`, корт `#1f75b3`, линии белые; красная `#E24B4A`, зелёная `#3DBE5A`; лучи и зона `#fac775` (зона с прозрачностью 0.2); мячи `#dcee34`, контур `#7a8f00`. Фон страницы и `theme-color` — `#0a1f33`.
- Ракетки: голова — эллипс rx 6, ry 9; струны 3 + 3 тонкие линии; рукоятка 2.6 × 15 с тремя насечками, **направлена вниз (положительные Y) у обеих ракеток**; вся ракетка повёрнута на 12°.
- Сетка «объёмная»: светлая полоса со штриховкой (диагонали + три горизонтали), тёмный верхний трос, тёмная нижняя линия-тень, стойки по краям.
- Надпись CITY TENNIS CENTRE: белая, шрифт 10, разрядка 1.5, прозрачность 0.35, у обеих задних линий; верхняя повёрнута на 180°.
- Переключатель «Розыгрыш / Подача» над кортом, активная кнопка `#378ADD`. Подсказка над ним, легенда под кортом (соперник / ваша позиция / зона приёма).
- Вне корта видны только надписи и ракетки; поле вокруг корта нужно, чтобы игроки могли выходить за линии.

## Допущения (владелец явно не подтверждал)

- «Задняя линия» в правиле выхода за боковые — нижняя (сторона зелёной); «боковые» — одиночного разряда.
- Игрок по Y всегда на задней линии независимо от режима и позиции соперника.
- Отступы 22.5 и 45 px — упрощение физики полёта мяча. Если владелец даст точные значения — обновить здесь.
